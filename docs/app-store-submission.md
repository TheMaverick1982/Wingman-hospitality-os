## ⚠️ Reviewer login (critical — this is the #1 rejection cause for apps behind a login)

Wingman is gated behind sign-in, so Apple/Google reviewers **cannot see the app**
unless you give them a working test account. Provide it in the review notes:

- Create a **dedicated demo account** in a demo organization with realistic
  sample data (a location, some guests, training, an audit) so the reviewer sees
  a working product, not empty screens.
- Put the **email + password** in:
  - Apple: App Store Connect → your app → **App Review Information → Sign-In required** (username/password fields).
  - Google: Play Console → **App content → App access** → provide credentials.
- Keep that account active and don't change its password until the app is live.

## App Privacy questionnaire (Apple "App Privacy" / Google "Data safety")

Wingman collects, at minimum:
- **Contact info:** name, email (account + team members) — used for app functionality, not tracking.
- **User content:** the operational data users enter (guests, training, audits).
- **Identifiers:** account/user IDs.
- **Usage/diagnostics:** analytics (you run GA/GTM — disclose it).

Declare data is **used for app functionality** and **not used to track users across
other apps/companies** (unless the analytics setup does — check GA config). Be
accurate; both stores audit this.

## Submission steps (when accounts + D-U-N-S are ready)

**iOS:**
1. App Store Connect → **+ New App** → pick the `app.joinwingman` bundle ID.
2. Fill listing (copy above), upload screenshots, set privacy answers, add the
   reviewer demo login.
3. In Xcode: select a real device / "Any iOS Device", **Product → Archive**, then
   **Distribute App → App Store Connect**.
4. Back in App Store Connect, attach the build → **Submit for Review**.

**Android:**
1. Play Console → **Create app** → set package `app.joinwingman`.
2. In Android Studio: **Build → Generate Signed Bundle (AAB)** (create an upload
   keystore — back it up safely, it's unrecoverable).
3. Upload the AAB to a **Production** (or Internal testing first) release, fill
   Data safety + App access, submit for review.

Tip: use **TestFlight** (iOS) and **Internal testing** (Android) to try the real
app on your own phone before public release.
